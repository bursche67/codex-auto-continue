# 验证记录

日期：2026-10-20（Asia/Shanghai）。

## 当前证据

- 技能格式校验：通过官方 `quick_validate.py`；另已检查 UI 元数据长度、默认提示词及引用文件存在。
- 开启及查看：应用工具成功创建并展示测试 heartbeat；保存的 TOML 为 ACTIVE，间隔 15 分钟，已核实绑定开发验收聊天。公开记录不包含真实聊天 ID 或本机运行配置。
- 测试定时任务用途：仅一次真实调度验收；技能交付后的首次有效触发记录结果并自动暂停，不代表已为其他业务任务开启监督。
- 配置控制：通过工具暂停同一 ID，读取确认 PAUSED；再通过工具重新启用，读取确认 ACTIVE、15 分钟间隔、正确聊天绑定、提示词标记及仅一个本聊天 ACTIVE 技能记录。没有创建第二份定时任务。
- 重复开启的语义识别、任务完成自动停用和审批场景：规则已写入技能，尚未通过真实任务验证；上述配置控制不等于这些行为测试通过。
- 真实定时触发：待验证。不能以创建成功或读取配置替代。
- 真实额度耗尽后恢复：待验证。目前没有耗尽额度，不主动制造耗尽。

## 验收步骤

1. 在有未完成目标的聊天调用技能，记录 ID、目标和聊天绑定；再次开启，核实复用同一 ID，只有一个 ACTIVE 记录。
2. 查看状态，核实保存的目标、状态和间隔；关闭后确认 PAUSED，再开启确认复用。
3. 留下可检验的未完成工作，等待真实定时唤醒，核实沿用原聊天和已有成果，且不重复启动执行。
4. 分别验证目标完成、等待用户回答、审批、用户暂停/取消；均应暂停监督，且不自行批准操作或反复通知。
5. 自然遇到额度耗尽时，记录适用额度桶、阻塞窗口、reset 时间和失败触发证据；确认后续调度仍 ACTIVE，额度真正恢复后的下一次有效触发继续原任务。周额度仍阻塞时不得推进。
6. 应用退出、电脑休眠和断网期间不承诺调度；恢复后查看真实触发结果，不将未执行的调度视为通过。

## 判定

额度耗尽后恢复为关键验收，未观察到完整链路前仅可称为“已配置的定时重试方案”。若失败触发导致后续调度停用，或恢复后不能继续，应记录失败并报告内置机制限制，不声称该方案已可靠实现无人值守恢复。
